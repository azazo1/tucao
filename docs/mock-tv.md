# mock 电视

投屏功能的测试替身. 用 python 模拟一台 DLNA 渲染设备, 在没有真电视时验证客户端的
发现, 控制, 进度同步, 以及防盗链导致的拉流失败.

## 它能做什么

- 响应 SSDP 的 `M-SEARCH`, 周期广播 `ssdp:alive`, 退出时广播 `ssdp:byebye`
- 提供设备描述与三个服务的 SCPD, 声明自己是一台 MediaRenderer
- 接受 AVTransport 的 `SetAVTransportURI`, `Play`, `Pause`, `Stop`, `Seek`
  与各种查询, 以及 RenderingControl 的音量控制
- 像真电视那样自己去拉媒体地址, 记录发出去的 `UA` 与 `Referer`
- 判断拉回来的东西是不是真能播: HTTP 状态, Content-Type, 封装签名, 时长
- 提供一个状态页当作"电视屏幕", 附带遥控器按钮
- 可选把画面交给 `ffplay` 显示, 用来确认"电视确实在放"

## 启动

```shell
# 默认: 自动挑局域网网卡, 自动生成 120 秒测试视频, 只探测不显示画面
just mock tv

# 带画面显示
just mock tv --play

# 手动指定对外地址 (开了 VPN 时常用, 自动挑选可能拿到 tun 的地址)
just mock tv --ip 192.168.1.108

# 局域网里已经有别的机器占了 1900 时, 只测状态页与拉流
just mock tv --no-notify
```

启动后终端会打印状态页地址, 设备描述地址和样本媒体地址. 手机需要和电脑在同一个
Wi-Fi 下.

## 状态页

`http://<本机局域网地址>:58920/`

- 传输状态, 当前位置与时长, 音量, 当前媒体, 拉流结果
- 遥控器按钮: 播放, 暂停, 停止, 音量增减, 用来模拟电视那边的按键
- 手动投递: 直接填一个媒体地址, 代替客户端下发, 便于单独验证拉流
- 最近日志: SOAP 动作, 媒体请求, 拉流判定, 权限拒绝原因

## 与真电视的差异

- 位置按墙钟推进, 不跟随 ffplay 的真实播放位置. 对客户端来说两者一致, 因为客户端
  本来也只能通过 `GetPositionInfo` 轮询.
- 只实现单实例与单个媒体, 不支持播放队列, 因此 `Next`/`Previous` 返回 UPnP 701.
- 事件订阅只回一个订阅号, 不做 GENA 通知. 客户端靠轮询工作即可.
- 不实现真正的视频解码, 画面交给 ffplay, 因此封装支持范围等于 ffmpeg 的能力.
- 不模拟品牌差异, 比如三星的字幕扩展字段, 松下的私有动作.

## 复现防盗链问题

站点直链部分带 Referer 校验, 手机播放器加载时带了 `Referer`,
电视端不带, 于是出现 "手机能播, 投屏后电视黑屏或报错". mock 把这个过程拆开:

1. 默认情况下 mock 拉流不带 `Referer`, 与真电视一致
2. 状态页的手动投递里填 `http://<地址>:58920/guard/sample.mp4`
3. 拉流结果会显示 `HTTP 403`, 并提示需要手机侧代理转发
4. 重新用 `just mock tv --referer http://<地址>:58920/` 启动, 再投一次, 变成 `HTTP 200`

`/media/` 路径不做校验, 用来对照. 客户端接上本地代理后,
真实站点地址也应达到同样的效果.

## 自检

```shell
# 以客户端身份跑完整流程: 发现, 投屏, 进度推进, 跳转, 暂停, 恢复, 停止
just mock probe

# 预期失败的一组: guard 路径需要 Referer
just mock probe --url http://192.168.1.108:58920/guard/sample.mp4
```

`probe` 本身也是一份调用顺序参考: 先 `SetAVTransportURI`, 再 `Play`,
之后轮询 `GetPositionInfo` 画进度, 退出时 `Stop`.

## 常见问题

### 手机发现不到设备

- 确认两者在同一网段, 不是访客网络, 路由器没有开启 AP 隔离
- 确认 mock 在终端里前台运行着, 终端打印的地址就是手机能用的地址
- macOS 会询问 "本地网络" 权限, 拒绝后组播发不出去, 表现为
  `No route to host`, 需要在系统设置的隐私与安全性里重新允许
- 开了 VPN 时, 自动挑选的地址可能落到 tun 上, 用 `--ip` 指定真实网卡地址

### 端口占用

- 58920 被占用时用 `--port` 换一个
- 1900 只允许一个程序独占组播组, 另一个 mock 或投屏软件在跑时会提示
  `Address already in use`, 关掉其一即可

### 没有 ffplay

`--play` 依赖 ffmpeg 自带的 ffplay. 缺失时只做拉流探测, 不影响控制流程的测试.

## 联调投屏功能时的验收清单

- 能在设备列表里看到这台电视, 名字是启动参数里的 `--name`
- 投屏后状态页的传输状态变成 `PLAYING`, 位置在走
- 手机上暂停, 继续, 拖动进度, 退出投屏, 状态页对应变化
- 拉流结果显示 `HTTP 200` 与 `video/mp4`, 没有 403
- 退出投屏后电视端回到 `STOPPED`, 手机上恢复本地播放并续到对应位置
